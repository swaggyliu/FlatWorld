按 README 里的实现，把这几个词对上代码。

**可变长度触觉 + Deep Sets（65–66 行）**

每一帧 EE 上的接触点数不固定：可能 0 个，也可能好几个。网络输入必须定长，所以补到 `K=16`：真接触 `mask=1`，空槽 `mask=0`。

Deep Sets 的做法是：每个接触先各自过 MLP，再按 mask **求和**（空槽不计入）。这样：

- 接触顺序打乱，结果不变（置换不变）
- 3 个接触还是 3 个接触，不依赖「第几个槽」（数量不变）

对应编码：

```96:100:learning/models/encoder.py
        tc = self.contact_mlp(contact_feat)
        tc = (tc * contact_mask.unsqueeze(-1)).sum(dim=1)
        tactile = self.tactile_proj(tc)
        s = self.summary_mlp(tactile_summary)
        return self.fusion(torch.cat([obj_pool, tactile, s], dim=-1))
```

**fusion**

不是单独一种算法，就是把几路特征 **拼起来再过 MLP**，压成 128 维潜变量 `z_t`：

- 物体图：节点 mean + max
- 触觉 Deep Set
- 触觉摘要（合力、接触数等）

`self.fusion(...)` 就是这个拼接 MLP。图里画在 Deep Sets 后面，实际物体分支也一起进去。

`z_enc`

当前观测编码出来的潜变量，代码里就是 `z`：`encoder(当前帧) → z`。  
`z_pred` 是用上一帧的 `z` 加动作、GRU 推出来的下一帧。  
`Recon(z_enc)`：拿编码出的 `z` 解码回物体状态，逼编码器别把信息丢掉。  
`Recon(z_pred)`：拿预测的 `z` 也解码，逼动力学别只在潜空间里对上、物理上却是胡编。

**SIGReg 为啥能防 collapse**

潜空间很容易「偷懒」：128 维里很多维变成常数，有效只剩几维。方差一塌，后面的 GRU 和 CEM 都不好用。

```114:117:learning/models/lewm.py
    def sigreg(z, target_std: float = 1.0):
        """SIGReg: hinge max(0, target_std - std(z_d)) against latent collapse."""
        std = z.flatten(0, -2).std(dim=0)
        return F.relu(target_std - std).mean()
```

对每一维：标准差若 `< 1`，就罚 `1 - std`；已经 `≥ 1` 则不罚（hinge）。这是「方差太小才打」，不是无脑最大化方差。名字来自这类 **SIGnal REGularization**（ variancel hinge），README 写的 `-var(z)` 是同一意图的简化说法。

**CEM 和 MPC**

- **MPC**：用模型往前看一段，选使代价最小的动作，执行第一步，再根据新观测重规划。这是一类方法。
- **CEM**：Cross-Entropy Method，这里用来 **在 MPC 里搜动作序列**：采样很多力序列 → 世界模型里展开 → 留精英 → 更新高斯 → 再采样。

关系：本仓库的规划器是 **用 CEM 做优化器的 MPC**。世界模型只负责「想象」，真推还是在仿真器里执行。

**OU（109 行）**

Ornstein–Uhlenbeck：有记忆的噪声，不是每帧独立乱抽。

```65:65:learning/data/collect.py
        a = c.ou_theta * prev + c.ou_sigma * rng.standard_normal(2)
```

`a_t ≈ 0.85 * a_{t-1} + 噪声`，力会平滑变化，末端不会每帧抽风。`free` 模式现在多半是「随机方向恒力扫一段时间 + 一点 OU」，README 那句还带着早期写法。

`clip` **不是防弹飞**

你标的附近是采目标距离：

```441:441:learning/tasks/push_to_goal.py
            dist = float(np.clip(self._free_run(obs, target_idx) - 0.02, 0.10, 0.30))
```

`free_run` = 目标右边到下一个物体之前还能走多远。`clip(..., 0.10, 0.30)` 是把 **目标点** 卡在 10–30 cm：

- 下限 0.10 > 成功阈值 0.08，开局不会已经成功
- 上限 0.30，不要求一次推半米

防末端被接触求解器弹到天上去的，是采集里的 **软围墙** `apply_barriers`（出界就往回加力），以及力的 `np.clip(a, -force_max, force_max)`。那是限执行器，不是限物体弹跳。

**GRU** 是 Gated Recurrent Unit，一种带门控的循环网络。这里只用一层 `GRUCell` 做潜空间动力学：输入是当前 `z` 拼上动作 `a`，隐状态 `h` 跨帧保留。

接触是突变的（刚碰上 / 刚离开），单看当前 `z` 不一定够马尔可夫，GRU 用来记「刚刚发生过接触」这类短历史。每一步：

```28:31:learning/models/predictor.py
    def step(self, z, a, h):
        """One-step transition. z (B,L), a (B,A), h (B,H) -> z' (B,L), h' (B,H)."""
        h = self.cell(torch.cat([z, a], dim=-1), h)
        return self.out(h), h
```

规划时就是把这个 `step` 在潜空间里连滚 H 步。

---

**和 JEPA 的关系：动力学确实只在潜空间比，但这个模型不是纯 JEPA。**

JEPA（Joint-Embedding Predictive Architecture）的核心是：预测也在表征里做，`z_pred ≈ sg(encoder(下一帧))`，**不**把像素/状态解码回来。本仓库里对应的就是动力学项：

```122:122:learning/models/lewm.py
        loss_dyn = F.mse_loss(out["z_pred"], out["z_target"])
```

`z_target = z[:, 1:].detach()`，下一帧编码器输出当目标，且 **stop-grad**，这和 JEPA/BYOL 一样，避免预测器与编码器串通成常数。

重建是 **额外** 加上去的，decoder 文件写得很直白：

```1:5:learning/models/decoder.py
"""StateTactileDecoder: latent z_t -> reconstructed (obj_states, tactile_summary).

Mandatory component: without the reconstruction loss the encoder can
collapse to a constant latent (dynamics loss alone is trivially zeroed
by a constant predictor output).
"""
```

原因有两层：

1. **防崩塌**：纯潜空间 MSE 在「所有 z 都是同一个常数」时也可以很小。JEPA 用非对称编码、stop-grad、EMA teacher 压这个；这里没有 EMA teacher，所以用 `Recon(z_enc)` + SIGReg 保证 z 还带着位置、速度等信息。
2. **给 CEM 用**：规划器要解码出物体坐标来算距离、挡路、骑乘。纯 JEPA 没有状态头，代价只能在潜空间编，这里做不到。`Recon(z_pred)` 还要求「推出来的 z 解回去仍是下一帧物理状态」，避免潜空间对上了、位置却是幻觉。

所以可以看成：**JEPA 式的潜空间预测 + 世界模型常用的解码器**。不是「只用 recon、不用潜空间」，而是两项都要：潜空间管「下一步像不像」，recon 管「z 里还有没有物理、规划能不能读」。

**GRU 和 RNN**

普通 RNN 每步就是：新隐状态 = `tanh(旧隐状态 + 输入)`。门全开，梯度沿时间连乘，十步以外容易没了（梯度消失），也容易一步把记忆冲掉。

GRU 多了两个门：

- **reset**：这一拍要不要先忘掉旧记忆再和输入混
- **update**：这一拍新内容占多少、旧 `h` 留多少

该记住的（刚发生的接触）可以长时间留在 `h` 里，该忘掉的（已经离开）可以清掉。LSTM 是三门 + 独立 cell，更重；GRU 是简化版，这个项目一步只要 `z` 和二维力，一层 GRUCell 够用。

这里如果换成无门 RNN，短 horizon（H=8）也许还能跑，接触这种「稀疏突变」更容易被冲掉。

---

**若改成 JEPA 策略，防崩塌一般加什么，这里有没有用**

纯 JEPA：预测只在潜空间，`z_pred ≈ sg(enc_target(下一帧))`，**训练时不解码**。防崩塌靠的是「目标分支不能跟着预测器一起变」，不是靠 recon。

常见组合（I-JEPA / BYOL 一类）：


| 手段              | 做什么                             | 在这套里                                  |
| --------------- | ------------------------------- | ------------------------------------- |
| **stop-grad**   | 目标 `z` 不回传到编码器                  | **已经有**：`z_target = z[:,1:].detach()` |
| **EMA teacher** | 目标编码器是学生的滑动平均，更新慢               | **没有**。这是 JEPA 最有效的防崩塌，值得加            |
| **非对称预测器**      | 只有学生这边有 GRU/MLP 预测头，teacher 只编码 | **已经有**：predictor 只在学生侧               |
| **表征归一化**       | latent LayerNorm / 除标准差         | fusion 已有 `out_norm`；SIGReg 是显式保方差    |
| **VICReg**      | 方差下限 + 维间去相关                    | 和现在的 SIGReg 同类，可加强（现在只保方差、不打协方差）      |
| **InfoNCE**     | 对比：真下一帧 vs 别的样本                 | 物理轨迹时间相关强，负样本难定义，收益不一定大               |


**会不会有效：防崩塌会，单独换 JEPA 不能替代现在的 recon。**

- EMA teacher + 现有 detach，潜空间预测会更稳，少出现「所有 z 挤成一点」。这和 JEPA 论文里的经验一致。
- 这边 CEM 的代价是 **解码后的坐标**（目标–goal 距离、挡路、骑乘）。纯 JEPA 没有状态头，规划器要么改成潜空间代价（难设计、也难保证「近」等于「推对了」），要么仍要一个解码器当探针——那又回到「JEPA 动力学 + 轻量 recon」。
- 你们现在的失败更多是 **接触/连锁推的幻觉**，不是 encoder 已经完全常数。`Recon(z_pred)` 专门打「潜空间对上了、物体却瞬移」。JEPA 不看状态，这种幻觉更难被训练看见；EMA 只能让表征更稳，不能告诉模型「箱子不该飞」。

比较务实的做法：动力学继续 JEPA 化（EMA teacher，可加 VICReg），**保留** `Recon(z_pred)` 给规划用，或只对 EE/目标位置做很弱的 recon。丢掉全部 recon、只比潜空间，在这个 PushToGoal 上多半会让 CEM 更瞎，而不是更像 I-JEPA 论文里的视觉表征。

## 以你们的目的，还值得做的

目标是：快、符合物理、动作出自世界模型。优先级建议是：

**1. 让模型真正学会连锁推（对游戏和 Random 都是瓶颈）**  
现在挡路靠开环大力，WM 对「A 撞 B、B 才动」仍然弱。CEM 才不敢信解码出来的目标运动。游戏里如果玩家要「挤过去 / 推箱子」，这块不过关，只能继续写规则。值得做：清路轨迹进训练（你们已经在采）、规划阶段少用脚本、代价里明确「先推开前面那个」。

**2. GPU 批量 CEM（游戏能不能 60Hz 的关键）**  
现在是 5×96 条序列在潜空间里滚。做游戏必须把 CEM 向量化，horizon 先 6–8，动作重复已经有 stride。否则「小人每帧问模型」会卡。

**3. 物体种类 / 数量泛化（游戏关卡用得上）**  
`improvement.md` 里的 capsule、多边形网格是对的。编码器按节点消息传递，理论上 N 可变，但训练写死 6 个刚体（EE+3 箱+2 球）。游戏要换关卡，需要：变长 N、类型 embedding、几何用半轴/半径（已有）或多边形顶点摘要。

**4. 能量项、辛积分：有用但不是第一刀**  
长程 open-loop（50 步）会更稳，少飘。规划 horizon 只有约 8 步，对 PushToGoal 成功率杠杆不如「接触+连锁」。游戏若要 **开环表演**（按一下看滚很远），再上这两项。

**5. 先别上 VAE 潜变量**  
CEM 要的是可解码的确定 `z`。Ensemble 的方差当不确定代价已经够用。VAE 会让规划更抖，除非你要「多种可能未来」的叙事，否则性价比低。

**6. 在线微调**  
有真机或玩家分布漂移再做。纯游戏、同一套 FlatWorld，DAgger 就够。

## 哪些点能提高泛化

- **域随机**：质量、摩擦、尺寸已经有；再加：物体个数、地面倾角、重力开/关、EE 半径。游戏关卡随机和训练 DR 对齐，模型才不会过拟合「3 箱 2 球」。
- **动作分布**：采集里要有「撞一下就停、擦边、大力清堆」。游戏动作若超出 6–8N 或乱抖，WM 会 OOD。
- **接触作为一等公民**：触觉已经进编码器；游戏受伤可以直接用现成的接触力，不必另训。
- **别让脚本越来越厚**：脚本越多，泛化越假。游戏版尽量 CEM 出动作，脚本只保底（防飞出屏幕）。



## 游戏策划：小球用世界模型走到目标

定位：**2D 物理益智 + 轻动作**，不是平台跳跃。玩家下 **意图**（点目标 / 选推哪个），**力由 CEM+世界模型给出**，仿真器执行。卖点是「这小球真会挤、会撞、会停」，不是魂类操作。

### 核心循环

1. 关卡：地面 + 箱子/球/刺/按钮，你的小球（现有 EE 球，可加一点重力或保持悬浮推力）。
2. 玩家点一个 **目标点** 或 **要推动的物体**（推箱子到坑里）。
3. 模型在潜空间规划一小段力，执行 1–几帧，再重规划（就是现在的 MPC）。
4. 碰到危险接触 → 掉血；推对机关 → 开门；到点且速度够慢 → 过关（和现在 success 条件一样）。



### 怎么玩有意思

**模式 A：搬运工（最贴现有代码）**  
把指定物推到星标。前方有挡路，模型要先清路。星级：时间、碰撞次数、有没有把别的东西推下悬崖。

**模式 B：别碰（你说的受伤）**  
完全能做，而且触觉已经有力。规则举例：

- 刺 / 红箱：接触力 `|F| > 阈值` 或接触帧数累计 → 掉血  
- 软垫：力大也不伤，鼓励「靠上去滑」  
- 连撞：短时间多次接触额外扣血，逼模型走「轻碰或绕开」而不是莽推

CEM 代价里加一项 `damage_cost`：想象轨迹上若会碰到红物体就加罚。这比再训一个「疼痛网络」靠谱，红物体用 `obj_types` 或一层语义标签即可。

**模式 C：弹球台 / 一杆**  
点方向，模型给一记冲量，看连锁把目标打进洞。最吃「A 撞 B」的世界模型，也最能展示 WM；现在最弱，当后期关。

**模式 D：护送**  
小球不能碰宝宝球，又要把挡路推开。代价：目标靠近 goal、同时惩罚与宝宝的接触。

**模式 E：双人**  
一人点目标，一人临时把某个箱子标成「烫」（本局受伤）。同一套物理，规则层变化。

### 受伤怎么接物理（不要另做血条仿真）

用现有 `contact_feat` 的力和 `contact_mask`：

- 伤害 = `k * max(0, |F| - F_safe)`，或按红物体接触帧  
- 击退可以仍走物理，不要「受伤瞬移」  
- 低血时 CEM 的 `force_cap` 变小：残血推不动堆，要换路线

这样受伤是物理的，不是 UI 扣血。

### 关卡节奏

1. **教学**：空地点到点（Leftmost 那种，走廊干净）
2. **轻碰**：路上一个软箱，擦过去不伤、撞死扣血
3. **搬运**：推黄箱到洞，灰箱可推可绕
4. **刺巷**：窄道两侧是刺，力要小、走中线
5. **堆**：必须清路，对应你们 Random 失败局
6. **终关**：护送 + 刺 + 限时

每关物体种类先只用球/箱，capsule/多边形等 WM 泛化后再加。

### 操作与表现

- 玩家：**点目标**，不要摇杆打力（力交给模型才是展示 WM）  
- 可选：按住「小心」→ 规划器降低 `fcap`、提高受伤权重  
- 画出 CEM 的几条淡轨迹（ensemble 分歧大就闪黄）：不确定时玩家会紧张  
- 失败回放：卡住 / 撞刺 / 推飞，对应你们 eval 图里的模式



### 技术约束（策划时就要写死）

- 一关刚体先 ≤ 8，和现在 N=6 同量级  
- 规划 20–30Hz，物理 60Hz，动作重复用现有 stride  
- 必须 GPU 批量 CEM，否则手机/网页吃不消  
- 出界仍用软围墙，当成「隐身墙」不要弹飞  
- 脚本清路可以当 **简单难度**；困难难度关掉脚本，只信 WM——这才是「用世界模型做游戏」的验收



### 建议的开发顺序

先做模式 A+B 一张刺巷教学关：点目标、接触掉血、CEM 出动作。模型侧优先把连锁推和批量规划做稳。能量项和辛积分放到「一杆打进洞」那种长轨迹模式再加。

这样 README 里还该做的，和游戏好玩的点是对齐的：**接触当伤害、图编码器撑多种摆法、CEM 给出动作、物理仿真当规则裁判**；能量/辛积分是后置的「滚得更像真物理」，不是第一款能玩的必要条件。

图形端和物理/世界模型分开最省事：Python 继续跑 FlatWorld + CEM，画面只负责把每帧的位置画漂亮。

## 建议：轻 2D，不要上 3D 引擎

目标是小球、箱子、地面，用 **正交 2D + 扁平矢量** 就够好看，也最轻。Unity/Unreal 对这种体量是杀鸡用牛刀。

**更像样的成品：PixiJS（WebGL 2D）**  

- 精灵、圆、圆角矩形、简单光晕都是 GPU 批量画，一关十来个刚体几乎零负担  
- 浏览器就能玩，分享方便  
- 物理仍在本机 Python：WebSocket 每帧丢 `[{id,x,y,theta,type,hp}]`，前端不管求解

视觉走「纸片物理」而不是写实：限制 3～4 个颜色、软阴影、接触时在接触点闪一下高光。比堆模型更能显得精致。

**先做原型、全留在 Python：raylib（**`pyray`**）或 Arcade**  

- 一个进程，调试 CEM 最方便  
- raylib 默认抗锯齿圆/矩形就比 matplotlib好看一档  
- 验证手感后再把同一套状态协议接到 Pixi

不建议一上来 Godot 里再做一套物理：两套碰撞会对不上，世界模型也会 OOD。Godot 若用，也只当「哑渲染器」。

## 怎么轻、又怎么漂亮

轻：关卡 mesh 极少、无骨骼、无后处理栈；60Hz 只同步刚体位姿；CEM 可以 20Hz 规划、中间帧插值。

漂亮靠这几招就够（都便宜）：

- 地面一条厚色带 + 轻微网格，不要贴大图  
- 箱子圆角、小球径向渐变，不要纯色方块  
- 接触力大时在接触点画一圈冲击波（数据已有 tactile）  
- 受伤物体用红色描边脉冲，不要粒子海  
- CEM 的候选轨迹画成半透明残影（你们 ensemble 分歧大时闪一下）——这是世界模型游戏的辨识度



## 和现有代码怎么接

FlatWorld 已经能 `gui.circle` / 画 box。游戏渲染器只订阅 `obj_states`、`obj_types`、`contact_feat`，不要在 JS 里重算物理。受伤用接触力阈值，图形端只表现，不做法官。

**一句话：** 玩法验证用 **Python + raylib/Arcade**；要好看、要给人玩，用 **PixiJS 2D + Python 仿真**，艺术方向定扁平矢量。
